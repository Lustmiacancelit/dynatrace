Start Here

For the normal Dynatrace Logs filter bar, your tenant works best with:

content = *500*
content = *Exception*
status = ERROR

Use content when searching inside the log text. Use status when filtering by Dynatrace severity.
Important: DQL commands like fetch logs | filter ... go in Logs → Open with / DQL mode, Notebooks, or Grail query. They do not belong in the normal filter bar.

content & status: What They Are For

content

content

Searches inside the actual log message text. Use this for endpoints, HTTP codes, trace IDs, exception names, account IDs, AWS errors, etc.

Logs filter bar
content = *500*
status

status

Filters by Dynatrace severity: ERROR, WARNING, INFO, NONE. Use this to reduce noise before searching content.

Logs filter bar
status = ERROR
loglevel

loglevel

Some apps also populate application log level. Use it if status does not match what you expect.

Logs filter bar
loglevel = ERROR
combined

Combine filters

Apply filters one by one as chips. This means ERROR logs that contain the endpoint.

Logs filter bar
status = ERROR
content = */gw/api/v1/sso*

Fix Your Example Query

Your example is close, but the quotes around JSON need escaping in DQL, and OR should usually be lowercase or. Also, in DQL status values are strings.

DQL

Correct DQL version

Find ERROR or WARN logs where the content contains the JSON instance path.

Use in DQL / Notebooks / Grail query mode
fetch logs
| filter status == "ERROR" or status == "WARN"
| filter matchesPhrase(content, "\"instance\":\"/gw/api/v1/sso\"")
| sort timestamp desc
| limit 100
DQL

Simpler DQL version

Easier if the JSON escaping is confusing: just search for the endpoint path.

Use in DQL / Notebooks / Grail query mode
fetch logs
| filter status in ("ERROR", "WARN")
| filter matchesPhrase(content, "/gw/api/v1/sso")
| sort timestamp desc
| limit 100

DQL Basics

A DQL query starts by loading data, then each line after | transforms or filters the data.
DQL

Basic logs query

fetch logs
| sort timestamp desc
| limit 100
DQL

Use timeframe in query

fetch logs, from: -24h
| sort timestamp desc
| limit 100
DQL

Absolute timeframe

fetch logs, timeframe: "2026-05-28T00:00:00Z/2026-05-29T00:00:00Z"
| sort timestamp desc
| limit 100
DQL

Filter errors

fetch logs
| filter status == "ERROR"
| sort timestamp desc
| limit 100

DQL Command Reference with Examples

This section does not include every single niche command option, but it includes the main command families you will use for troubleshooting, reporting, and dashboards.

fetch

fetch

Loads data: logs, spans, events, bizevents, metrics depending on availability.

fetch logs, from: -2h
| limit 100
filter

filter

Keeps only matching records.

fetch logs
| filter status == "ERROR"
| filter matchesPhrase(content, "timeout")
sort

sort

Sorts records.

fetch logs
| sort timestamp desc
| limit 100
limit

limit

Limits result count.

fetch logs
| limit 50
fields

fields

Shows only selected fields.

fetch logs
| fields timestamp, status, content, k8s.pod.name
| limit 100
fieldsAdd

fieldsAdd

Adds calculated fields.

fetch logs
| fieldsAdd short_message = substring(content, 0, 120)
| fields timestamp, status, short_message
fieldsRemove

fieldsRemove

Removes fields from output.

fetch logs
| fieldsRemove content
| limit 100
summarize

summarize

Aggregates records.

fetch logs
| summarize count(), by:{status}
| sort count desc
makeTimeseries

makeTimeseries

Creates time-series data for charts.

fetch logs, from: -24h
| filter status == "ERROR"
| makeTimeseries errors = count(), interval: 15m
parse

parse

Extracts values from text.

fetch logs
| filter matchesPhrase(content, "traceId")
| parse content, "LD 'traceId\":\"' LD:traceId '\"' LD"
| fields timestamp, traceId, content
| limit 100
expand

expand

Expands array values into rows.

fetch logs
| fields timestamp, tags
| expand tags
| limit 100
dedup

dedup

Removes duplicates by a field.

fetch logs
| dedup content
| limit 100
lookup

lookup

Joins/enriches with another dataset when available.

fetch logs
| lookup [ fetch events ], sourceField:dt.entity.host, lookupField:dt.entity.host
join

join

Combines records from two subqueries when supported.

fetch logs
| filter status == "ERROR"
| join [ fetch spans | fields trace.id, request.url ], on:{trace.id}
append

append

Appends results from another query.

fetch logs
| filter status == "ERROR"
| append [ fetch logs | filter status == "WARNING" ]
data

data

Creates inline test data.

data record(status="ERROR", count=10),
     record(status="WARN", count=5)

DQL Functions & Operators

matchesPhrase

matchesPhrase

Best function for phrase/token matching in content.

fetch logs
| filter matchesPhrase(content, "Internal Server Error")
contains

contains

Substring search. Useful for exact text fragments.

fetch logs
| filter contains(content, "/gw/api/v1/sso")
startsWith

startsWith

Checks beginning of a field.

fetch logs
| filter startsWith(content, "ERROR")
endsWith

endsWith

Checks end of a field.

fetch logs
| filter endsWith(log.source, "application.log")
in

in

Checks if a value is in a list.

fetch logs
| filter status in ("ERROR", "WARN")
isNull

isNull / isNotNull

Checks missing/present fields.

fetch logs
| filter isNotNull(k8s.pod.name)
count

count

Counts records.

fetch logs
| summarize total = count()
countIf

countIf

Counts only records meeting condition.

fetch logs
| summarize errors = countIf(status == "ERROR"), warnings = countIf(status == "WARN")
avg/min/max

avg / min / max

Common aggregations, especially for spans/metrics.

fetch spans
| summarize avg_duration = avg(duration), max_duration = max(duration), by:{request.url}
toString

toString

Casts values to string.

fetch logs
| fieldsAdd status_text = toString(status)
substring

substring

Creates shorter message previews.

fetch logs
| fieldsAdd preview = substring(content, 0, 200)
lower

lower / upper

Normalize case for comparisons.

fetch logs
| filter contains(lower(content), "timeout")

Troubleshooting Workflows

Workflow

API 500

  1. Filter bar: content = *500*
  2. Filter bar: content = */your/endpoint*
  3. DQL: search endpoint + status ERROR.
  4. Open log details and look for traceId/requestId.
  5. Go to Distributed Tracing or Services → Failures.
Workflow

No logs found

  1. Increase timeframe to Last 24 hours or Last 7 days.
  2. Clear all filters.
  3. Search content = *INFO* or use no content search.
  4. Check Log source / K8s / Host facets.
Workflow

Timeout

  1. content = *timeout*
  2. content = *504*
  3. content = *Read timed out*
  4. Check slow spans in Distributed Tracing.
Workflow

Kubernetes crash

  1. content = *CrashLoopBackOff*
  2. content = *OOMKilled*
  3. Filter by pod or namespace.
  4. Open Kubernetes → Workloads → Events.

Reusable Patterns

Best normal Logs filter bar pattern:
content = *keyword*
Best DQL pattern:
fetch logs | filter matchesPhrase(content, "keyword") | sort timestamp desc
Do not quote an entire OR expression as text:
Bad: content = *"500 OR 501 OR 502"*
Better: use one search at a time in the filter bar, or use DQL with multiple or conditions.
